# 《我关注的100位小红书科技博主》对外内容标准 V0.1

适用范围：博主档案系列的图片、标题、正文、标签和发布前检查。

## 1. 栏目角色

对外身份不是“站在旁边评价博主的人”，而是一个真的花时间翻内容、找原文、做核验，再把发现讲给朋友听的研究者。

读者应该感受到三件事：

1. **我真的看过**：有明确的阅读量、时间范围、代表内容和研究过程。
2. **我发现了意外**：不是把主页简介换一种说法，而是展示研究前后认知发生了什么变化。
3. **我还会继续做**：给出值得复现、值得核验或值得继续追踪的下一步。

第一人称只用于交代观察、转折和判断，不要每段都以“我认为”开头。观点仍应由事实和例子站住。

## 2. 8 页图片叙事模板

每页只完成一个任务，并在结尾自然把读者带向下一页。

| 页码 | 任务 | 推荐句式 | 内容上限 |
|---|---|---|---:|
| 1 | 研究动作 + 结果钩子 | `我翻完___篇 / 真正记住的 / 是这___件事` | 标题3行 + 3个线索 |
| 2 | 研究前后的认知反差 | `我原以为___，翻完后发现___` | 1段 + 3个数字 |
| 3 | 第一条最意外的线索 | `最让我意外的不是___，而是___` | 1段 + 4个例子 |
| 4 | 一条可以立刻带走的方法 | `我把这条___拆开后，发现它有效在___` | 1段 + 3步 |
| 5 | 一处不能直接照抄的内容 | `这里有一处我不会照抄` | 1段 + 事实校正 |
| 6 | 多条内容放在一起后的共同主线 | `把这几期内容放在一起，我看到___` | 1段 + 3个概念 |
| 7 | 风险、边界或真正值得停下来的问题 | `真正让我停下来的是___` | 1段 + 4条清单 |
| 8 | 我的关注理由 + 开放问题 | `我会因为这3件事继续关注___` | 3条 + 1个问题 |

### 每页内部顺序

1. **一句抓人的判断**：先说这页为什么值得看。
2. **一个具体例子或机制**：不能只有形容词。
3. **一条边界或下一步**：告诉读者什么还没被证明，或可以怎么继续。

证据等级放在页底窄条，不占用主叙事。A/B/C 是严谨性的保障，不应让图片读起来像审计报告。

## 3. 图片语言

优先使用：

- `我原以为……`
- `翻到这里时，我才意识到……`
- `最让我意外的是……`
- `我把这条方法拆开后……`
- `这里有一处我不会直接照抄……`
- `把这几篇放在一起看……`
- `我准备继续验证的是……`

避免使用：

- `该博主的内容模式是……`
- `适合因为什么关注该账号……`
- `综合来看，该账号……`
- 连续多页以名字作主语：`小盖认为 / 小盖提到 / 小盖表示`
- 只有结论、没有研究动作或具体例子的“报告体”
- “起底”“终极”“全网最全”等不能被交付物支撑的夸张词

## 4. 标题模板

发布标题控制在 18—22 个汉字内，优先“研究动作 + 数字 + 认知结果”：

- `我翻完___篇，记住了这___件事`
- `看完___个月内容，我重新认识了___`
- `我把___的高赞内容翻了一遍`
- `研究完___，我决定继续追这___条线`

标题必须准确，不把约数写成精确值，不把未验证主张写成事实。

每期保留 3 个候选标题：

1. 数字证明型
2. 认知反差型
3. 线索好奇型

## 5. 正文模板

### 开头：先讲为什么真的去翻

用一个自然动作开场，不先介绍栏目使命：

> 我最近用了一个有点笨的办法：想看懂一个博主，就一直往前翻，直到能看出他反复在讲什么。

紧接研究范围：看了多少、覆盖多久、数据快照是什么时候。

### 中段：用“原以为—后来发现—最值得继续”的递进

1. 研究前的印象。
2. 翻完后的认知变化。
3. 3—5 条最具体的发现。
4. 至少一处事实校正或未解决项。
5. 自己准备继续复现或追踪什么。

正文不逐字复述 8 张图。图片负责“读懂”，正文负责“让我相信你真的研究过”。

### 结尾：开放，而不是盖棺定论

- 说明这是一份可被纠正的研究快照。
- 邀请博主本人补充来源。
- 给出 GitHub 档案和查询 Skill。
- 只留一个互动问题：`下一位，你想让我翻谁？`

## 6. 标签模板

每篇 7—10 个标签，按以下顺序组织：

1. 栏目与身份：`#科技博主` `#内容研究`
2. 大类：`#AI` `#人工智能`
3. 本期核心主题 3—4 个：如 `#Codex` `#Agent` `#OpenClaw` `#播客`
4. 方法或场景 1—2 个：如 `#提示词` `#AI工具`

不要堆与正文无关的泛流量词；不要同时使用大量近义标签。

## 7. 发布前检查

- 读完第 2 页，是否能看出“我原来怎么想、后来怎么变”？
- 每页是否至少有一个具体产品、例子、数字或机制？
- 相邻两页是否有自然递进，而不是 7 张独立资料卡？
- 第一人称是否只承担观察和判断，没有变成自我表演？
- A/B/C、日期、热度和链接是否与 GitHub 数据一致？
- 是否明确写出至少一个未解决项，没有猜链接？
- 正文是否像人说话，连续朗读时没有报告腔？
- 标签是否与本期内容逐一对应？
