# 《我关注的100位小红书科技博主》对外内容标准 V0.2

适用范围：博主档案系列的图片、标题、正文、标签和发布前检查。

## 1. 栏目要回答什么

一篇博主档案首先要回答：

> 这个人为什么值得关注，他稳定提供的价值是什么？

不能先挑几篇热门帖子，再把主题强行串成一篇文章。代表内容只负责证明对创作者的判断，不能替代对创作者的判断。

完整研究顺序：

1. 识别全部内容中反复出现的选材偏好、信息来源和表达方式。
2. 找到这个账号为读者持续解决的问题。
3. 解释这些能力为什么会形成关注、收藏和转发。
4. 用代表内容证明上述判断。
5. 最后给出值得优先阅读的内容和关注理由。

## 2. 栏目角色

对外身份是认真研究过创作者的内容策展人。

第一人称只承担两种作用：

- 交代研究动作，例如“我翻了多少内容”。
- 明确关注理由，例如“我为什么会继续关注”。

正文中心必须是博主的能力、内容特点和读者价值。不能连续使用“我原以为”“我很意外”“我准备验证”等句式，让帖子变成研究者的个人日记。

每个判断都要能被内容样本、明确来源或具体例子支撑。

## 3. 8 页叙事结构

| 页码 | 页面任务 | 必须回答的问题 |
|---|---|---|
| 1 | 封面 | 这位博主为什么值得关注？标题控制为两行，并配头像与主页公开介绍。 |
| 2 | 账号定位 | 他稳定为读者提供什么价值？ |
| 3 | 核心能力一 | 他从哪里找到信息，选材强在哪里？ |
| 4 | 核心能力二 | 他如何提炼、转述和形成观点？ |
| 5 | 核心能力三 | 他如何把信息落到行动或具体场景？ |
| 6 | 受欢迎机制 | 为什么读者愿意关注、收藏和转发？ |
| 7 | 代表内容 | 哪些内容最能证明前面的判断？ |
| 8 | 总结与互动 | 我关注他的三至五个原因；还有谁值得关注？ |

相邻页面必须形成因果关系：

`信息从哪里来 → 如何被选择 → 如何被提炼 → 如何对读者有用 → 哪些内容能证明`

## 4. 图片内容规则

### 先讲能力，再讲主题

优先写：

- `他持续从 X、播客和演讲里筛选高密度信息`
- `他会从长内容里只抓一个最有张力的问题`
- `他把工具信息继续翻译成普通人可以尝试的动作`

避免写：

- `第一条线索是 OpenClaw`
- `第二条线索是提示词`
- `第三条线索是 Codex`

后者只是主题清单，不能证明创作者为什么值得关注。

### 用具体指向替代内部标记

对外图片不得出现：

- `产品能力 A`
- `原始 X 作者 C`
- `事故原因 B`
- `数据快照`
- 只有编辑本人能理解的缩写和核验术语

需要展示来源时，直接写清：

- `Lenny's Podcast × Notion 产品负责人 Max Schoening`
- `Anthropic 对四名大学生的官方访谈`
- `第九届数字中国建设峰会 Agent 治理论坛`

A/B/C、核验日期、未解决项和完整 URL 只进入后台档案及来源清单。

小红书图片和发布正文不得直接露出 GitHub URL、安装命令或技术同步机制。对外跟进入口统一使用笔记挂载的小红书 Skill；正文可以自然提示读者下载或安装 Skill。

### 删除不服务阅读的内容

一项内容只有在满足以下至少一个条件时才进入图片：

- 帮助读者理解博主的能力。
- 为前面的判断提供具体证据。
- 给读者一个清晰的阅读入口。
- 推进整篇叙事。

否则删除。严谨不等于把后台研究字段全部搬到前台。

## 5. 视觉层级

- 黄色眉题是当前页面的一级分论点，不是小标签。
- 眉题字号应为主标题的 70%—85%，视觉重量接近主标题。
- 眉题与标题之间只保留一层明确层级，避免“小字提示 + 超大标题”造成误读。
- 封面主标题固定为 2 行；正文页主标题控制在 2—3 行。
- 封面头像必须和博主姓名、主页公开介绍组成一个信息组，不使用与正文脱节的悬浮头像。
- 正文控制在 4—6 行；每页只解释一个判断。
- 页面底部不放冗长研究说明、快照日期或模糊证据条。
- 暖白背景、黑字、青色和橙色强调保持不变。

## 6. 标题策略

发布标题优先提出“为什么值得关注”，而不是强调研究者的情绪：

- `___为什么值得关注？我翻完___篇`
- `看懂___，不能只看他发了什么`
- `我为什么会一直关注___`
- `___真正厉害的，不只是更新快`

数字用来证明研究投入，不能成为内容主角。

## 7. 正文结构

1. 用一句自然的话说明为什么想认真研究这位博主。
2. 先给账号定位，不先列热门主题。
3. 展开三项稳定能力：信息来源、提炼方式、落地能力。
4. 解释这些能力给读者创造了什么价值。
5. 最后给出三至四类代表内容作为阅读入口。
6. 完整链接和研究边界放到后台档案，不在小红书正文暴露 URL。
7. 说明栏目会持续整理创作者档案，并提示可通过本篇挂载的 Skill 跟进。
8. 以 `欢迎你持续关注并提交你的宝藏博主！` 收尾。

正文可以有明确观点，但不能只写个人感受。读者看完后应该能复述：

- 这个博主擅长什么。
- 他为什么会受欢迎。
- 我应该从哪几篇开始看。

## 8. 标签模板

每篇 7—10 个标签：

1. 栏目身份：`#科技博主` `#AI博主` `#内容研究`
2. 大类：`#AI` `#人工智能`
3. 创作者主要领域：如 `#AI工具` `#播客` `#Agent`
4. 内容形态或场景：如 `#科技内容`

不堆与正文无关的产品名。

## 9. 发布前检查

- 去掉代表帖子后，是否仍能说清这个博主为什么值得关注？
- 代表内容是否在证明能力，而不是承担主线？
- 是否说明了信息从哪里来、如何被提炼、怎样对读者有用？
- 每个来源是否写成普通读者能理解的具体名称？
- 图片中是否还残留 A/B/C、快照日期或编辑内部术语？
- 第一人称是否只用于研究凭证和关注理由？
- 眉题和主标题的字号是否接近？
- 最后一页是否明确总结三至五个关注理由？
- 最后一页是否说明可通过本篇挂载的 Skill 跟进后续档案？
- 图片和发布正文是否完全没有 GitHub URL、安装命令或其他外链？
- 封面是否为两行标题，并紧接头像、姓名和主页公开介绍？
- 最后问题是否为：`欢迎你持续关注并提交你的宝藏博主！`
